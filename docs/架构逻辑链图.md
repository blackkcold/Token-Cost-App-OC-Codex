# 架构逻辑链图

## 三系统全景架构

Public App 仓库包含 macOS 与 Android 两个客户端；Private Relay 和 Public Contract 使用 sibling repositories。macOS 是数据所有者，Android 通过 E2EE Relay 与其通信。

```mermaid
graph TB
    subgraph "macOS 桌面端 (Sources/)"
        MAC_AGG[本地数据聚合<br/>OpenCode + Codex 双源]
        MAC_BAL[Provider 余额查询]
        MAC_RELAY[中继 PC 端<br/>接收查询请求并返回余额快照]
        MAC_STATE[本地状态持久化]
    end

    subgraph "安卓配套 App (android/)"
        AND_PAIR[扫码配对交互]
        AND_RELAY[中继 App 端<br/>发起查询请求]
        AND_DISPLAY[四 Tab 仪表盘<br/>总览/图表/余额/设置]
        AND_STORE[DashboardStore 共享状态层<br/>身份/刷新/缓存/撤销]
        AND_BG[可选后台监控<br/>WorkManager 周期 + 显式前台服务]
        AND_DISPLAY --> AND_STORE
        AND_STORE --> AND_RELAY
        AND_BG --> AND_RELAY
    end

    subgraph "Private Relay (separate repository)"
        RELAY_FWD[设备间消息转发]
        RELAY_HEALTH[可用性/健康检查端点]
        RELAY_BOUND[部署边界<br/>仅转发端到端加密信封]
    end

    MAC_AGG --> MAC_BAL
    MAC_BAL --> MAC_RELAY
    MAC_RELAY <-->|WebSocket 转发| RELAY_FWD
    AND_RELAY <-->|HTTPS 转发| RELAY_FWD
    AND_PAIR --> AND_STORE
    RELAY_FWD --> RELAY_HEALTH
```

> Private Relay 不持有 Provider 凭证或 E2EE Key，只转发不透明信封。Public App 仅保留 Contract v1 snapshot，不包含服务端、Admin、Database 或部署实现。Contract 1.2 草案将 App Token、E2EE Key、请求/响应与终端会话绑定到同一 `keyVersion`。

## Relay Protocol v1

```mermaid
flowchart LR
    MAC[macOS Relay Client] -->|WS relay.response| PRIVATE[Private Relay]
    PRIVATE -->|WS relay.request| MAC
    ANDROID[Android Relay Client] -->|HTTPS requestId + envelope| PRIVATE
    PRIVATE -->|HTTPS response| ANDROID
    CONTRACT[Public Contract v1] -.schemas + vectors.-> MAC
    CONTRACT -.schemas + vectors.-> ANDROID
    CONTRACT -.schemas + vectors.-> PRIVATE
```

Pairing QR 字段固定为 `version/deviceID/keyVersion/pairCode/e2eKey/expiresAtMilliseconds`，不携带 Endpoint。Release 客户端从受保护构建配置读取相同的 HTTPS Endpoint。新终端先进入 `PENDING`；Mac 持久化 pending key journal 后激活，Relay 在单事务内将旧 `ACTIVE` 变为 `REPLACED`。只有通过安全校验的用户查询续期七天活动 TTL。
