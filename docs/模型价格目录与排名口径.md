# 模型价格目录与排名口径

> 适用版本：2026-10 起的 macOS / Android 客户端模型排行。
> 关联：`docs/Token统计口径定义.md` §3.1、`Sources/CodexTokenCostCore/ModelPricingCatalog.swift`

## 1. 为什么不再手写模型 ID

旧实现把「模型价格」写在 `DashboardAnalytics.swift` 的 `zenPricing` / `deepSeekLegacyPricing` 两张常量表里，而「能否归并」「能否进排行」又都由这两张表派生。结果是：任何新模型（例如 `deepseek-v4.1-flash:1017`）都必须改代码才能显示，否则 `tokensPerDollar = 0`，被排序压到末尾、再被默认 Top 10 折叠隐藏。

现在价格来自 **models.dev 目录**，模型 ID 由数据自动发现：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1（最高） | `~/Library/Application Support/com.yanghaoran.CodexTokenCost/model-prices.json` | 用户手动覆盖，无需改代码 |
| 2 | 同目录 `model-price-index.json` | 客户端每 24h 从 `https://models.dev/api.json` 抓取后压缩落盘 |
| 3 | `~/.cache/opencode/models.json` | OpenCode 自己维护的 models.dev 缓存 |
| 4（兜底） | 内置快照 | 与旧版常量表完全一致，离线可复现历史口径 |

`model-prices.json` 格式（可选，仅用于目录里确实没有的模型）：

```json
{
  "providers": {
    "openai": {
      "gpt-6.1-sol": { "input": 1.25, "output": 5.00, "cache_read": 0.125, "cache_write": 1.25 }
    }
  }
}
```

价格单位统一为 **USD / 1M tokens**；`reasoning` 缺省时按 `output` 计价。

## 2. 变体归并规则

`ModelPricingCatalog.splitVariants` 只剥离「同模型的构建/发行修饰」，绝不合并语义不同的模型：

| 归并 | 不归并 | 原因 |
|---|---|---|
| `:1017` `:0731` `:cloud` | `v4` vs `v4.1` | 语义版本价格不同（ollama-cloud 0.22 vs 0.15） |
| `-cloud` `-fast` `-preview` `-latest` `-edge` `-thinking` | `-mini` `-pro` `-max` | 是不同 SKU，不是同一模型的部署差异 |
| `-YYYYMMDD` 日期后缀 | `-free` | 免费档必须独立成行，永不继承付费价 |
|  | `-exp` | 实验模型保留自身身份 |

示例（真实数据）：

| 原始 ID | 家族键 | 命中方式 | 单价 in/out/cacheRead |
|---|---|---|---|
| `deepseek-v4.1-flash:1017` | `deepseek-v4.1-flash` | exact / variant | 0.15 / 0.60 / 0.003 |
| `deepseek-v4-flash:0731-cloud` | `deepseek-v4-flash` | variant（`:0731` 精确价） | 0.22 / 0.66 / 0.007 |
| `glm-5.3-flash:cloud` | `glm-5.3-flash` | variant | 0.15 / 0.50 / 0.03 |
| `deepseek-v4.1-flash-free` | `deepseek-v4.1-flash-free` | exact（0 价）或按名推定免费 | 0 / 0 / 0 |
| `gpt-6-luna-fast` | `gpt-6-luna` | variant（继承，界面标注） | 0.10 / 0.50 / 0.01 |
| `gpt-6.1-sol` | `gpt-6.1-sol` | unknown | — |

## 3. 排名语义

`ModelComparisonRow.pricingStatus` 四态：

- `exact`：目录里就是这个 ID 的价格
- `inherited`：价格借自更具体的构建键或基础模型，界面显示「沿用 <键>」
- `free`：已知免费（目录价全 0，或 ID 后缀为 `free` 且目录无条目）
- `unknown`：任何地方都查不到价格，`price = nil`

排序固定为 **免费 → 已定价（tokens/$ 降序）→ 未定价（按用量降序）**。未定价模型**不会消失**，也不会被伪装成 $0；卡片底部显示「另有 N 个模型未显示」与「价格目录：models.dev · 截至 <日期> · N 个模型未定价」。

Provider 级兜底成本（`syntheticApiCost`、订阅价、`rawCost`）**保持旧口径不变**，因此补价格不会让总费用突然跳变；变化只发生在「模型 API 等值」排行与 Relay `cost.models`。

## 4. 迁移核查（本机真实库，最近 30 天）

脚本：`script/model_pricing_delta.py`（旧常量表自动从 `DashboardAnalytics.swift` 解析，避免口径漂移）。

| 指标 | 旧口径 | 目录口径 |
|---|---|---|
| 模型级 API 等值合计 | $114.07 | $338.75 |
| 解析命中（行） | — | exact 21,262 / freeInferred 1,074 / variant 1,028 / unknown 499 |
| 仍未定价 | 13 个 `(provider, model)` / 18,746 行 | **1 个 / 499 行** |

主要来源：

- `openai` 与 `deepseek` 之前完全没有模型级价格，现在按目录计价（$196.41 / $10.11）。
- `deepseek-v4.1-flash` 家族（含 `:1017`）从 $0 变为 $63.05，回到排行正常位置。
- `glm-5.3-flash` 旧逻辑因最长前缀误命中 `glm-5`（1.00/3.20），实际是 0.15/0.50，单模型从 $109.28 降到 $16.40——这是本次顺带修掉的计价错误。
- 唯一仍未定价：`gpt-6.1-sol`（499 行），可用 `model-prices.json` 覆盖。

> 该表是模型级「API 等值」费用，不代表订阅/配额账单；Provider 总费用口径未变。

## 5. 刷新与离线

- 启动后首次进入详情页触发一次检查；索引文件 `fetchedAt` 在 24h 内不重复请求。
- 请求失败、离线、目录损坏均静默回退到上一份索引或内置快照。
- 刷新成功后通过 `ModelPricingCatalogStore.didUpdateNotification` 通知界面重建分析结果，无需重启。
- 仅请求公开的 `https://models.dev/api.json`，不携带任何本地数据。
