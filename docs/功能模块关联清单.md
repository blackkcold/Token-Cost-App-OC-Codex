## 1. 数据源管线

### 1.1 OpenCode 管线（SQLite → 仪表盘）

| 阶段 | 文件 | 职责 |
|------|------|------|
| 来源发现 | `SourceDiscoveryService.swift` | 扫描文件系统发现 SQLite 数据库 |
| 数据读取 | `TokenDatabaseClient.swift` | `json_extract` 查询 → `DashboardPayload` |
| 数据模型 | `Models.swift` | `DashboardPayload`, `RawRow`, `Summary` |
| 分析引擎 | `DashboardAnalytics.swift` | Overview/Cache/Provider Rank/Model Comparison/Trend |
| 数据 Store | `TokenCostModel.swift` | MVVM 状态管理、快照持久化、设置加载 |
| 展示页面 | `DetailView.swift`, `TrendChartView.swift`, `SidebarView.swift`, `OpenCodePageView.swift` | 侧边栏 + 详情仪表盘 + 共享趋势图 |

**关键约束**：OpenCode SQLite 中 `$.tokens.input` 字段**已是非缓存值**。代码中所有 `actualTokens` 计算均用 `input + output + reasoning`，不再额外减去 `cacheRead` 或 `cacheWrite`。

### 1.2 Codex 管线（JSONL → 仪表盘）

| 阶段 | 文件 | 职责 |
|------|------|------|
| 来源配置 | `SourceProfiles.swift` | Codex 默认扫描路径 |
| 子进程调用 | `CodexHelperRunner.swift` → `CodexTokenCostHelper` | 外部进程采集 session 文件 |
| 数据解析 | `CodexSessionCollector.swift` | JSONL 逐行解析 → `CodexDashboardPayload` |
| 数据模型 | `CodexModels.swift` | `CodexTokenUsage`, `CodexSessionSummary` |
| 分析引擎 | `CodexAnalytics.swift` | 趋势点聚合、session 排序 |
| 数据 Store | `CodexSessionModel.swift` | MVVM 状态管理、快照持久化 |
| 展示页面 | `CodexPageView.swift`, `TrendChartView.swift` | Session 列表 + 共享趋势图 |

**数据差异**：Codex JSONL 中 `inputTokens` 包含缓存，因此 `actualInputTokens = max(inputTokens - cachedInputTokens, 0)`。与 OpenCode 管线不同，不做 `cacheWrite` 减法（Codex 无此字段）。

### 2.2 费用分析（API + 订阅双口径）

- 每模型 API 定价表（`TokenCostPricingCatalog.zenPricing`）

### 2.3 Provider 订阅计划管理

- 五提供商的官方订阅 / Token Plan 预设：OpenCode Go/Zen、ChatGPT Plus/Pro/Business、MiniMax Token Plan、Xiaomi MiMo Token Plan；DeepSeek 仅 API 按量计费，无固定月费方案
- 自定义 USD 月费：用于应对官方价格变更
- 每个 Provider 的订阅覆盖独立判断：已启用固定订阅计算订阅月费；否则计算 API 成本，统一合并出总成本；设置页订阅 Picker 只展示固定月费型方案，API/paygo 通过关闭订阅开关进入计算链路
- 订阅周期设置（开发者模式门控）：每个 Provider 独立设置起止日期（`periodStart`/`periodEnd`，包含式日历日，起止均计入）、粒度（`PeriodGranularity.day/.month`）、快捷预设（`PeriodPreset.monthly/.quarterly/.yearly`）；`periodTotalCost(for:)` 按粒度折算该 provider 的完整周期总成本；`hasPeriodTracking` 开关控制是否启用周期跟踪，关闭时回退月费口径（`monthlyUSD`）；原生 SwiftUI `DatePicker`（`.date` 模式）直接作为起止日期输入控件，不做额外日期转换
- **全局报告范围（Reporting Range）**：`reportingRangeMode`（`allAvailable`/`currentMonth`/`last30Days`/`custom`）定义全局报告窗口。`reportingCostBreakdown(payload:reportingStart:reportingEnd:)` 是规范总成本入口——Phase 1 将各 provider 的独立周期成本按重叠天数分摊到报告范围（`cycleTotalCost × overlapDays / cycleIncludedDays`），无重叠贡献 0，无周期/无效日期回退完整 `monthlyUSD`；Phase 2 补充报告范围内未被固定订阅覆盖的 API 用量成本。`combinedTotalCost(payload:)` 优先使用 `reportingCostBreakdown`，payload 无法形成有效范围时回退 `combinedMonthlyCost`
- **关键文件**: `BillingPlanCatalog.swift`（含 `PeriodGranularity`/`PeriodPreset` enum、`periodTotalCost`/`combinedPeriodCost`/`reportingCostBreakdown`/`combinedTotalCost`/`filteredPayloadWithReportingOverrides` 方法，以及 `ReportingCostBreakdown` 结构体）, `AppPreferences.swift`（含 `ReportingRangeMode`/`ReportingRangeCustomBounds`）, `AppPreferencesModel.swift`（含 per-provider binding + 500ms 去抖 + `applyPeriodPreset` 快捷填充）
- **UI**: `SettingsView.swift`（计费方案卡片）, `BillingSectionView.swift`（`reportingRangeSection` 全局范围 Picker + 自定义 DatePicker 面板；`periodTrackingSection` 含 `hasPeriodTracking` Toggle、`PeriodPreset` segmented Picker、`customPeriodEditors` 原生 DatePicker 控件）, `TotalView.swift`（总览使用 `combinedMonthlyCost` + 开发者模式下追加 `combinedPeriodCost` 副文本；全局报告范围生效时使用 `combinedTotalCost`）, `MenuBarView.swift`（菜单栏月费卡片追加周期总成本副文本）
- **分析注入**: `TokenCostDashboardAnalytics` 接收 `billingOverridesByProviderKey`，应用于 provider effective cost；`filteredPayloadWithReportingOverrides` 为全局报告范围生成过滤后的 payload 和固定成本覆盖映射

### 2.8 安全边界

### 2.13 版本更新检查

- 启动时每天一次自动静默检查 GitHub Release 最新版本（24h 缓存）
- 工具栏左侧始终显示「检查更新」按钮，可手动触发即时检查（忽略缓存）

- 无更新时显示「已是最新版本 vX.Y.Z」（3 秒自动消失）
- 下载进度以胶囊标签背景左→右渐进填充可视
- 自动安装要求 Release 提供 Ed25519 签名 update manifest；prepareVerifiedUpdate(from:) 先验证版本/Bundle ID/架构/文件名/长度/SHA-256/Ed25519 签名，再流式下载到权限受限 staging 目录（最大 512MB），任何失败清理临时产物；解压后仍通过 codesign --verify --deep --strict 验证
- 下载后校验文件大小 × Content-Length 交叉验证
- **关键文件**: `UpdateChecker.swift`（Service）、`UpdateCheckerModel.swift`（Store、含 `manualCheck`/`dismissUpdate`）、`ContentView.swift`（工具栏 7 态 UI）、`Localizable.strings`（4 个新增 key）

### 2.15 响应式悬浮余额面板（Floating Panel）

- 无边框 `NSPanel`（`BalanceFloatingPanelWindow`），`level: .floating` 始终置顶，`collectionBehavior: [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary]`，`hidesOnDeactivate = false` 跨桌面常驻

- **边框**：使用中性 `surfaceAccessibleStroke` 替代蓝色 `surfaceStroke`，双层细线叠加（0.55 + 0.35 透明度）
- 两种显示模式：`.normal`（`BalanceProviderCardView` 完整卡片）和 `.minimal`（`BalanceMinimalProviderTile` 紧凑磁贴），通过 `balanceFloatingPanelDisplayMode` 偏好切换

- `BalanceFloatingPanelCoordinator` 管理面板生命周期：`@Published preferences.balanceFloatingPanelEnabled` 驱动显示/隐藏，关闭按钮写回 `false` 持久化

- 设置页余额分区提供启用开关和显示模式 Picker
- **关键文件**: `BalanceFloatingPanelView.swift`, `BalanceFloatingPanelLayout.swift`, `BalanceFloatingPanelCoordinator.swift`, `BalanceMinimalProviderTile.swift`, `BalanceProviderCardView.swift`, `VisualEffectBackground.swift`, `AppPreferences.swift`（`balanceFloatingPanelEnabled`/`balanceFloatingPanelDisplayMode`）, `AppPreferencesModel.swift`（对应 Binding）, `BalanceSectionView.swift`（设置 UI）, `MenuBarView.swift`（菜单栏开关）, `AppDelegate.swift`（`requestInitialPresentation()`）, `TokenCostApp.swift`（Coordinator 初始化注入）

## 4. 约束与边界（修改功能前必读）

1. **App 纯本地运行为主**——除版本更新检查（仅匿名 GET `api.github.com`，不上传数据）和余额查询（可选开启、HTTPS 直连官方 API）外，不接入网络。所有数据来自本地文件系统。
2. **源数据只读**——不修改 OpenCode SQLite 或 Codex JSONL 文件。只写配置到 Application Support。
3. **OpenCode vs Codex 公式差异**——不要强行统一两端的 actual token 公式。两端数据模型不同。
4. **input 字段语义**——OpenCode SQLite 的 `input` 已是非缓存值。不要再做 `input - cacheRead - cacheWrite` 减法。
5. **订阅费用回退机制**——`DashboardAnalytics.providerEffectiveCosts` 以 billingOverridesByProviderKey 为第一优先级，未覆盖时回退到 legacyFallbackMonthlyCosts，最后兜底 raw/synthetic api cost。
6. **不要引入第三方依赖**——当前仅有 sqlite3 系统库。不要加 Markdown 渲染库或网络库。
7. **所有 UI 文案走 `AppLocalization`**——不要在任何 View 中硬编码中/英文字符串。
8. **代码注释只在必要时添加**——公开 API 需要 doc comment 说明参数/行为；内部逻辑优先通过清晰的命名自我表达。
