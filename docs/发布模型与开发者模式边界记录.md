## 1. 当前分发状态

### 1.1 构建方式

项目使用 Swift Package Manager 构建。CI 和本地开发均通过同一命令：

```bash
swift build          # Debug
swift build -c release  # Release
```

三个 SPM target：
- `CodexTokenCostCore` — 核心模块
- `CodexTokenCostApp` — 主应用（可执行 target）
- `CodexTokenCostHelper` — 辅助进程（可执行 target）

### 1.2 代码签名

当前签名策略为 ad-hoc 签名，不附带任何开发者身份：

```bash
codesign --force --deep --sign -
```

| 签名参数 | 当前值 | 说明 |
|---------|--------|------|
| `--force` | 使用 | 强制覆盖已有签名 |
| `--deep` | 使用 | 递归签名 bundle 内所有组件 |
| `--sign -` | 使用 | ad-hoc 签名（无 Developer ID） |
| `--options runtime` | 不使用 | 无 Hardened Runtime |
| `--entitleties` | 不指定 | 无权限文件 |
| Developer ID | 无 | 未注册 Apple Developer 身份 |

### 1.3 Notarization

**未经过公证**。当前分发操作不包括 notarization 步骤。

### 1.4 Entitlements

**项目中不存在 `.entitlements` 文件**。App 当前运行在非沙箱环境中。

### 1.5 分发渠道

仅通过 **GitHub Releases** 分发，格式为 `.zip` 压缩包。

发布流程：
1. `swift build -c release`
2. `codesign --force --deep --sign -` 签名
3. 打包为 `.zip`
4. 上传到 GitHub Releases
5. 用户下载后手动解压、移动至 Applications

### 1.6 Sandbox

**无沙箱**。App 当前未启用 App Sandbox，因此可以自由访问文件系统中的 allowlist 路径。这也是 Developer Mode 的局部文件扫描能力在当前分发模型下可行的前提。

## 2. 安全边界来源

Developer Mode 的安全边界不依赖平台分发约束，而是由应用自身实现。这意味着即使分发模型改变，以下安全机制仍然有效：

### 2.1 应用内 Allowlist / Blocklist

文件访问策略由 `DeveloperFileAccessPolicy` 实现，在应用代码层面硬编码。

- Allowlist：精确到单文件或目录级别的可读路径
- Blocklist：精确到单文件或目录级别的拒绝路径
- 策略在编译时确定，不可由用户配置绕过

### 2.2 fd-based Metadata Access

使用 `DeveloperFileHandle`（类型标记 `~Copyable`）通过系统调用的 fd 操作获取文件元数据。

核心链路：`openat()` → `fstatat()` → `fstat()` → 返回 `DeveloperFileAttributes`。

关键特性：
- 逐组件解析路径（非字符串拼接）
- `O_NOFOLLOW` 防止 symlink 逃逸
- `O_CLOEXEC` 防止 fd 泄漏至子进程
- `deinit` 自动关闭 fd
- 不含 `fcntl(F_GETPATH)` 回退（macOS 上不安全）

### 2.3 独立目录 + CI banned-symbol Enforcement

Developer Mode 的所有代码位于独立目录：

```
Sources/CodexTokenCostCore/DeveloperMode/
Sources/CodexTokenCostApp/DeveloperMode/
```

CI 通过 `script/check_developer_mode_banned_symbols.sh` 和 `script/developer_mode_sources.manifest` 确保这些目录中不出现禁止符号（内容读取、网络请求、凭证访问等）。

操作列表由 `script/developer_mode_sources.manifest` 定义，并由 GitHub Actions 在每次 push/PR 时强制执行。`swift build` 前执行检查，`swift build` 和 `swift test` 随后运行。

### 2.4 运行时无网络/无凭证依赖

Developer Mode 的 Phase 0-3 能力不需要网络连接或凭证访问。这意味着：

- 可在离线下正常运行
- 不依赖外部服务可用性
- 不暴露凭证到新的攻击面
- 测试不需要模拟网络环境

## 3. 不新增 .entitlements 的理由

### 3.1 当前 App 无沙箱

App 当前通过 ad-hoc 签名分发，不启用 App Sandbox。即使不新增 entitlements，Developer Mode 的文件扫描能力在当前分发模型下完全合法。

### 3.2 Developer Mode 安全边界不依赖 entitlements

如前所述，Developer Mode 的安全边界来自：

- 应用内 allowlist/blocklist（硬编码策略）
- fd-based 系统调用（PATH→FD→metadata 的原子化操作）
- CI banned-symbol enforcement（防止代码退化）
- 运行时无网络/无凭证（缩小攻击面）

这些机制不需要 entitlements 来保证。entitlements 只能限制 app 能做什么（平台级约束），不能防止 app 内部做不该做的事（逻辑级约束）。Developer Mode 需要的是后者。

### 3.3 若未来目标包含 MAS，需重新评估

如果未来计划将 Token Cost App 提交到 Mac App Store：

- App Sandbox 将成为强制要求，entitlements 是必要条件
- Developer Mode 的文件扫描能力需要 `com.apple.security.files.user-selected.read-only` 或 `com.apple.security.files.read-write` 等 sandbox read entitlement
- 当前 allowlist 中部分路径（`~/.codex/sessions/`、`~/.config/opencode/skills/`）在沙箱下需要用户通过 Open/Save panel 显式授予访问权限，无法由 app 自行声明
- Developer Mode 不能作为隐藏功能进入 MAS 审核（违反 2.3.1(a) 禁止 hidden/dormant/undocumented feature）
- 届时需要重新评估 Developer Mode 的定位：是保留为独立分发的高级功能，还是适配沙箱并提供用户引导

## 4. Apple Review Guidelines 相关约束

以下列出与 Developer Mode 设计相关的 Apple Review Guidelines 条款，供参考。

### 4.1 2.2 / 2.3.1(a) — 不隐藏功能

> 2.2: Apps must be fully functional and provide value to users.
> 2.3.1(a): Apps with hidden, dormant, or undocumented features are rejected.

**对 Developer Mode 的影响**：

在非 MAS 分发的（ad-hoc）情况下，此条款不构成直接约束。但如果未来提交 MAS：

- Developer Mode 不能作为"隐藏灰度壳"存在
- 所有子功能必须在 App Store 描述中披露
- 不能利用 Developer Mode 的开关来控制审核时不可见的功能

### 4.2 2.4.5(i) / 2.4.5(vii) — 沙箱要求

> 2.4.5(i): Apps distributed through the Mac App Store must be sandboxed.
> 2.4.5(vii): Apps may not download or install additional code for use within the app.

**对 Developer Mode 的影响**：

- MAS app 必须沙箱化，开发者模式的文件扫描权限受到限制
- Developer Mode 的自动更新机制可能不适用于 MAS 版本

### 4.3 2.5.2 — 自包含

> 2.5.2: Apps should be self-contained. An app may not access the user's home directory in a broad or indiscriminate manner.

**对 Developer Mode 的影响**：

- Developer Mode 不能递归扫描整个用户家目录
- Allowlist 必须精确到单文件或目录级
- Blocklist 范围已涵盖常见敏感路径
- 所有扫描行为有明确目的，不"顺带读取"

### 4.4 5.1.1 / 5.1.2 — 数据最小化

> 5.1.1: Data Collection and Storage: Apps should collect only the data that is necessary to provide the intended functionality.
> 5.1.2: Data Use and Sharing: Apps must obtain explicit consent before collecting or sharing data.

**对 Developer Mode 的影响**：

- v1 只读元数据，不读文件内容，符合数据最小化原则
- Phase 4 AI 分析必须在收集前单独征求用户同意，并提供清晰的隐私披露
- 数据最小化原则也适用于本地治理视图：不展示完整文件内容，只展示必要元数据

## 5. Developer Mode 在不同分发模型下的状态矩阵

| 分发场景 | Sandbox | Entitlements | Developer Mode 可行性 | 备注 |
|---------|---------|-------------|---------------------|------|
| Ad-hoc（当前） | 否 | 无 | 完全可行 | 保持状态 |
| Developer ID（Gatekeeper） | 否 | 需要 hardened runtime | 可行，但需 --options runtime | 未来可考虑 |
| Mac App Store | 是 | 需要 sandbox 相关 | 需重新评估 | 文件扫描受限 |
