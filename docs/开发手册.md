# 开发手册

## 1. 项目概述

**Token Cost App - OC Codex** 是一个 macOS 原生桌面应用，用于可视化 AI 编程工具（OpenCode / Codex）产生的 token 用量和费用数据。

- **语言**: Swift 6.0+
- **UI 框架**: SwiftUI + AppKit (部分)
- **构建系统**: Swift Package Manager (SPM)
- **最低系统**: macOS 14.0 (Sonoma)
- **仓库**: [GitHub](#) · MIT License

### 数据源

| 数据源 | 格式 | 默认路径 |
|--------|------|---------|
| **OpenCode** | SQLite 数据库 | `~/.local/share/opencode/opencode.db` |
| **Codex** | JSONL 文本文件 | `~/.codex/sessions/` |

## 3. 模块架构

### 3.1 CodexTokenCostCore（核心库）

最底层模块，不依赖 AppKit / SwiftUI。被 App 和 Helper 共享引用。

| 文件 | 职责 |
|------|------|
| `Models.swift` | 数据模型：`TokenCostSource`, `TokenCostSettings`, `DashboardPayload`, `UsageAggregateRow` |
| `AppPreferences.swift` | 全局偏好：语言、总览计价模式、Provider 计费方案选择、本地持久化 |
| `BillingPlanCatalog.swift` | Provider 计费计划目录：OpenCode、ChatGPT/Codex、MiniMax、Xiaomi MiMo 官方预设与自定义 USD 月费解析 |
| `Localization.swift` | 语言切换与本地化资源加载 |
| `CodexModels.swift` | Codex 专用模型：`CodexTokenUsage`, `CodexSessionSummary`, `CodexDashboardPayload` |
| `DashboardAnalytics.swift` | 分析引擎：将原始行转为 Overview / Cache / Provider Rank / Model Comparison / Distribution / Trend / Stacked。**含模型定价目录**（`TokenCostPricingCatalog`） |
| `CodexAnalytics.swift` | Codex 分析：session 排序、日期桶聚合、趋势点生成 |
| `TokenHeatmapBuilder.swift` | 双源热力图数据构建：合并 OpenCode / Codex 日 token、生成 52 周窗口、输出 7x52 兼容矩阵和按日期升序的响应式 cells |
| `CodexBilling.swift` | 废弃常量（不再参与主计算链） |
| `TokenDatabaseClient.swift` | SQLite 客户端：探针 + `json_extract` 查询 + 构建 `DashboardPayload` |
| `SourceDiscoveryService.swift` | 文件系统扫描：遍历目录发现数据库文件。`lastModified` 字段以 ISO 8601 UTC 格式存储，UI 层通过 `TokenCostFormatters.localDateTime(_:)` 转换为用户系统时区显示 |
| `CodexSessionCollector.swift` | JSONL session 解析器：读取每行 JSON、提取 `session_meta` 和 `event_msg(token_count)` |
| `SourceProfiles.swift` | OpenCode / Codex 的默认路径、文件模式、扫描深度等配置 |
| `SettingsStore.swift` | 设置 + 快照文件的读写和轮转 |
| `SafeFileStore.swift` | 沙箱内安全文件操作（防止路径穿越） |
| `UpdateChecker.swift` | GitHub Release 检测、.zip 下载（异步进度回调）、完整性校验、ditto 解压 |
| `PathUtilities.swift` | 路径标准化、descent 检查 |
| `AppPaths.swift` / `CodexSessionPaths.swift` | 路径常量 |
| `Theme.swift` | 主题枚举 |

### 3.2 CodexTokenCostApp（主应用）

依赖 Core 模块。`@main` 入口。

| 目录 | 职责 |
|------|------|
| `App/` | `@main` 入口、AppDelegate、路径常量、菜单命令 |
| `Stores/` | `TokenCostModel`（OpenCode 数据层）、`CodexSessionModel`（Codex 数据层）、`AppPreferencesModel`（全局偏好桥接）、`UpdateCheckerModel`（版本更新状态机）、`CodexSnapshotStore` |
| `Views/` | 所有 SwiftUI 视图（6 个主要页面 + 通用组件）。`Components.swift` 含 `TokenCostFormatters` 枚举（token/currency/percent/localDateTime 格式化）和 `TokenMetricCard`（指标卡片组件，支持 compact 模式和统一高度约束）；`TrendChartView.swift` 提供 OpenCode / Codex 共享趋势图；`TokenHeatmapGrid.swift` 提供总计页响应式热力图 |
| `Services/` | `CodexHelperRunner`（通过 `Process` 调起 Helper 子进程） |
| `Support/` | `ThemePalette`（主题调色板）、`SeriesPalette`（图表配色）、`WindowLifecycleManager`（激活策略管理，窗口关闭时隐藏 Dock 图标） |
| `Resources/` | App target 内置资源，例如 `Pricing.md` 只读计费参考文档 |

### 3.3 CodexTokenCostHelper（辅助进程）

独立可执行文件，由主 App 通过子进程方式调用。

| 文件 | 职责 |
|------|------|
| `main.swift` | CLI 入口：解析 `--source-root` / `--manual-source-path` 参数 |
| `CodexSessionCollector.swift` | 采集 Codex session 文件，解析为 `CodexDashboardPayload`，输出 JSON 到 stdout |

### 3.4 应用级偏好与本地化

应用级偏好不和 OpenCode / Codex 各自的数据源设置混用，而是单独保存：

- `AppPreferencesStore` 负责把 `language`、`openCodePricingMode`、`billingSelectionsByProvider`、`theme`、`displayCurrency`、`balanceEnabled`、`balanceRefreshMinutes`、`balanceConfig` 写入本地 `config/app-preferences.json`
- `AppPreferencesModel` 是 SwiftUI 侧的单一状态入口，负责保存和广播语言切换、主题变更。采用内存缓存 + 写穿透模式：UI 从 `@Published preferences` 内存读取，变更时通过 `SafeFileStore` 以 `.atomic` 原子写入 JSON，并在覆盖前保留备份；不做主线程写后 sleep 回读校验
- 余额监控相关的 Provider 开关和 `allowEnvironmentCredentials` 不允许在 View 中直接改 `preferences.balanceConfig` 嵌套字段，而是统一经 `AppPreferencesModel.updateBalanceConfiguration()` 修改并立即持久化，避免运行时状态与磁盘状态短暂漂移
- `AppPreferencesModel` 也负责 OpenCode Go `workspaceID` 的兼容同步：保留 `app-preferences.json` 中的副本，用户编辑保存时同步写入 Keychain，供运行时凭证发现链路读取；Settings 页提供「测试连接」按钮用于验证当前 OpenCode Go 凭证
- `SettingsView` 已按 `全局偏好 / 计费方案 / 余额监控 / OpenCode / Codex / Skills 面板 / 安全边界` 分组；一级模块可折叠，warning banner 常驻顶部，OpenCode / Codex 的长路径列表保留二级折叠与分页；模块内部统一使用响应式控制网格、动作条和字段区，默认在 900 宽设置窗口内优先两列排布，窗口变宽后再扩到更多列
- `BalanceManager` 在 App 启动时从 `AppPreferences.balanceConfig` 初始化，并在设置变更时热更新；OpenCode Go 只有在 `allowEnvironmentCredentials == true` 时才允许读取 `OPENCODE_GO_WORKSPACE_ID` / `OPENCODE_GO_AUTH_COOKIE`
- `ContentView` 监听 `scenePhase`，在 app 进入后台或非活跃状态时强制执行一次所有设置域的最终落盘（`persistPreferences()` + `persistSettings()`），防止系统强杀时数据丢失
- `AppLocalization` 从 `Resources/<lang>.lproj/Localizable.strings` 读取文案，并在 App 运行时根据语言切换刷新 UI
- 总览页只读取 `openCodePricingMode`；其中 OpenCode 的“实际 token”指标按 `input + output + reasoning` 计算（各字段含义与 OpenCode 源码 `getUsage()` 存储逻辑一致：`input` 在 SQLite 中已是非缓存输入，`output` 为非推理输出，`reasoning` 为推理 token，`cacheRead`/`cacheWrite` 为独立缓存字段），OpenCode / Codex 独立页面仍保留各自原有 token 统计与展示口径
- Provider 订阅成本通过 `BillingPlanCatalog` 解析：每个 Provider 独立判断——已启用固定订阅算月费，否则走 API/raw/synthetic cost。总成本 = 已启用固定订阅费用 + 未订阅部分 API 估算成本；全部订阅关闭时总成本全部按 API 估算。选择 DIY 时统一按 USD/月保存并注入 `TokenCostDashboardAnalytics` 的 provider effective cost
- `PricingDocView` 从 `Bundle.module` 读取 app target 内置的 `Pricing.md`，手动分段解析标题、引用块和表格，过滤 markdown 分隔符行（`|---|---|`），使用原生 `HStack` + `Divider` 渲染表格；不打开任意本地路径、不访问网络；`Package.swift` 通过 `.process("Resources")` 打包该资源
- 技术词统一保留英文写法，例如 `token`、`API`、`OpenCode`、`Codex`、`ChatGPT Plus`

## 4. 数据流

### 4.1 OpenCode 数据管线

```
[文件系统扫描]
SourceDiscoveryService
    ↓ discover()
[SQLite 数据库列表] → TokenCostSource[]
    ↓ 用户选择来源
[TokenDatabaseClient.loadPayload()]
    ↓ SELECT json_extract(...) FROM message
[UsageAggregateRow[]]
    ↓ buildPayload()
[DashboardPayload]
    ↓ TokenCostDashboardAnalytics 初始化（可接收 billingOverridesByProviderKey）
[Overview / Cache / Provider / Model / Distribution / Trend]
    ↓ 各 View 读取
[UI 渲染]
```

**关键 SQL**: 使用 `json_extract(data, '$.tokens.input')` 等从 JSON 列提取字段，按 `date, model_id, provider_id` 分组聚合。

### 4.2 Codex 数据管线

```
[用户在设置中配置 session 目录/文件]
    ↓
[CodexHelperRunner.loadPayload()]
    ↓ 启动子进程
[CodexTokenCostHelper (外部进程)]
    ↓ 遍历 JSONL 文件
[CodexSessionCollector.loadPayload()]
    ↓ 逐行解析 session_meta / event_msg
[CodexDashboardPayload]
    ↓ stdout JSON → 主进程解码
[CodexSessionModel.payload]
    ↓ CodexDashboardAnalytics 分析
[UI 渲染: 趋势图 + Session 列表]
```

**Error 处理**: Helper 进程超时 15s，失败自动回退到本地快照 `~/Library/Application Support/com.yanghaoran.CodexTokenCost/snapshots/codex/`。

## 5. 编译、构建与打包

### 5.1 编译验证

| 命令 | 作用 | 产物 |
|------|------|------|
| `swift build` | Debug 编译验证 | `.build/` |
| `swift build -c release` | Release 编译验证 | `.build/` |

这两条命令只负责编译，不承诺 `release/` 下的发布目录。

> 备注：如果当前 shell 访问 `~/.cache/clang/ModuleCache` 受限，可以改用 `HOME=/private/tmp swift build --disable-sandbox`；`script/build_and_run_codex.sh` 已内置这条兜底路径。

### 5.2 本地构建 app

```bash
bash script/build_and_run_codex.sh build
```

- 版本号默认读取最近的 git tag，格式为 `vX.Y.Z`
- 本地构建必须落在 `release/` 下的独立子目录中，目录名固定为 `release/vX.Y.Z-YYYYMMDD-HHMMSS-<pid>/`
- 这个本地子目录只保存当前开发状态的 app bundle，不覆盖正式 release 目录
- 生成的 app bundle 名称固定为 `Token Cost App - OC Codex.app`
- 构建脚本会把 `Resources/` 整体复制进 `Contents/Resources/`，所以 `zh-Hans.lproj` 和 `en.lproj` 会随 app 一起打包
- SPM app target 也会通过 `.process("Resources")` 打包 `Sources/CodexTokenCostApp/Resources/Pricing.md`，供 `PricingDocView` 在 app 内只读展示
- `CFBundleDevelopmentRegion` 设为 `zh-Hans`，默认文案基准是中文
- `run`、`debug`、`logs`、`telemetry`、`verify` 也使用同一套本地 staging 命名

### 5.3 正式 Release 打包

```bash
RELEASE_VERSION=v0.8.0 bash script/build_and_run_codex.sh release
```

- 正式 release 目录固定为 `release/vX.Y.Z/`
- 同目录下生成版本化 zip：`Token-Cost-App-OC-Codex-vX.Y.Z-macOS-{arch}.zip`（arch 为 `arm64` 或 `x86_64`，由构建脚本自动检测）
- app bundle 名称固定为 `Token Cost App - OC Codex.app`
- 构建脚本自动更新 `release/latest/` 和 `release/versions.json`
- GitHub Actions 的 `release.yml` 会注入当前 tag 作为 `RELEASE_VERSION`

### 5.4 依赖

- macOS 14.0+
- Xcode / Command Line Tools (提供 `xcrun`, `swift`, `lldb`)
- SQLite3 (系统自带)
- 无其他外部依赖

## 6. 版本与命名规则

### 语义化版本 (SemVer)

```
MAJOR.MINOR.PATCH
0.1.1
```

| 变更类型 | 版本 | Git 操作 |
|---------|------|---------|
| 大重构 / 不兼容变更 | MAJOR | `git tag -a v1.0.0 -m "..."` |
| 新功能 | MINOR | `git tag -a v0.3.0 -m "..."` |
| Bug 修复 | PATCH | `git tag -a v0.2.1 -m "..."` |

### 6.1 命名矩阵

| 场景 | 命名规则 | 说明 |
|------|----------|------|
| 编译验证 | `.build/` | 只做编译校验，不生成发布目录 |
| 本地构建 app | `release/vX.Y.Z-YYYYMMDD-HHMMSS-<pid>/` | `vX.Y.Z` 取最近 git tag，时间戳和 PID 只用于避免覆盖 |
| 正式 release | `release/vX.Y.Z/` | 只保留版本号，不混入时间戳 |

### 6.2 发布产物

- app bundle 名称固定为 `Token Cost App - OC Codex.app`
- 正式 release zip 命名格式：`Token-Cost-App-OC-Codex-vX.Y.Z-macOS-{arch}.zip`
  - 示例：`Token-Cost-App-OC-Codex-v0.8.0-macOS-arm64.zip`
  - `{arch}` 为 `uname -m` 输出（`arm64` / `x86_64`），由构建脚本自动检测
- zip 与 app bundle 同目录保存（`release/vX.Y.Z/`）
- `release/latest/` 始终指向最新构建产物（.app 和 .zip），所有构建模式（run/build/release）均会更新
- `release/versions.json` 记录正式 release 的结构化元数据（版本号、日期、文件名），仅 release 模式写入

### 发布流程（完整 PR 工作流）

> ⚠️ **强制要求**：所有发版必须通过 Pull Request 流程，禁止直接 push 到 main。

```
阶段 1: 功能开发
├── 从 main 创建 feature 分支：git checkout -b feature/vX.Y.Z-{feature-name}
├── 实现功能、修复 bug，提交到 feature 分支
└── 更新 CHANGELOG.md（在 Unreleased 区记录变更）

阶段 2: PR 提交与合并
├── git push origin feature/vX.Y.Z-{feature-name}
├── 在 GitHub 创建 Pull Request: feature/vX.Y.Z → main
├── PR 标题格式：release: vX.Y.Z — {简要描述}
├── PR 描述：列出 Added / Fixed / Changed / Security
├── Code Review → 通过后点击 "Merge pull request"（使用 merge commit）

阶段 3: 更新 CHANGELOG 并打 Tag（在 main 上）
├── git checkout main && git pull origin main
├── 将 `Unreleased` 中本次变更固化为 `## [vX.Y.Z] - YYYY-MM-DD`
├── 建议立即补回新的 `## [Unreleased]` 顶部区块，并把目标版本指向下一版（例如 `v0.8.2`）
├── 同步更新 SECURITY.md 的支持版本范围
├── 在 release/release-notes/ 创建 vX.Y.Z.md（中英双语 release notes）
├── git add → git commit -m "release: vX.Y.Z — 正式发版"
├── 打 annotated tag：git tag -a vX.Y.Z -m "vX.Y.Z — {简要描述}"
└── git push origin main --tags（⚠️ 不要用 --tags 推所有旧 tag）

阶段 4: 本地构建 Release 产物
├── RELEASE_VERSION=vX.Y.Z bash script/build_and_run_codex.sh release
├── 产物位于 release/vX.Y.Z/
│   ├── Token Cost App - OC Codex.app
│   └── Token-Cost-App-OC-Codex-vX.Y.Z-macOS-{arch}.zip
└── 构建脚本自动更新 release/versions.json

阶段 5: 推送 tag 触发 GitHub Release 工作流
├── `.github/workflows/release.yml` 在 tag push 时自动执行
├── 自动运行：RELEASE_VERSION=vX.Y.Z bash script/build_and_run_codex.sh release
├── 自动读取：release/release-notes/vX.Y.Z.md 作为 GitHub Release 正文
├── 自动上传：release/vX.Y.Z/Token-Cost-App-OC-Codex-vX.Y.Z-macOS-{arch}.zip
└── 验证：GitHub Actions 与 Releases 页面都显示成功，asset 与 release notes 完整

阶段 5.1: 自动工作流失效时的手工兜底
├── gh release create vX.Y.Z \
│     --title "vX.Y.Z — {标题}" \
│     --notes-file "release/release-notes/vX.Y.Z.md" \
│     "release/vX.Y.Z/Token-Cost-App-OC-Codex-vX.Y.Z-macOS-{arch}.zip"
└── 仅在 Actions 无法正常创建 Release 时使用

阶段 6: 收尾
├── 将 release/versions.json 的变更提交：git add release/versions.json && git commit && git push
├── 刷新 README.md（版本徽章、最新版链接、功能列表）
└── git push origin main
```

**关键检查点**：
- [ ] PR 已通过 review 并在 GitHub 上合并（非本地 merge）
- [ ] CHANGELOG.md 中 `vX.Y.Z` 条目日期已更新；若保留新的 `Unreleased` 顶部区块，必须明确指向下一版
- [ ] SECURITY.md 支持版本已更新
- [ ] release-notes/vX.Y.Z.md 已创建（中英双语）
- [ ] Tag 已推送到 origin（仅推当前 tag，不要 `--tags`）
- [ ] Release zip 命名格式正确：`Token-Cost-App-OC-Codex-vX.Y.Z-macOS-{arch}.zip`
- [ ] GitHub Release 已创建，包含正确的 zip asset 和 `release/release-notes/vX.Y.Z.md` 内容
- [ ] README.md 已刷新

### 6.3 发版同步要求

- 每次准备发布前，必须同步检查并更新 `CHANGELOG.md` 与 `SECURITY.md`
- `CHANGELOG.md` 负责记录本次变更和对应版本号，`SECURITY.md` 负责记录当前支持的安全版本范围
- 在未打正式 tag 之前，不要把 `Unreleased` 写成已发布版本；`Unreleased` 里应保留相对当前稳定版的累计变更，等 `vX.Y.Z` tag 推送后，再把对应条目定稿为正式 release，并把新的 `Unreleased` 目标切到下一版
- 若发布版本号发生变化，`script/build_and_run_codex.sh`、GitHub Release 目录和 zip 命名必须保持一致
- 清理 `release/` 目录时，至少保留 1 份正式 release 和 1 份独立的最新带时间戳本地构建快照；旧快照再移动到垃圾桶。`release/latest/`、`release/versions.json` 和 `release/release-notes/` 不可删除

遵循 [Keep a Changelog](https://keepachangelog.com/)：

```markdown

### Added
- 新增 CI/CD 自动化工作流
- 新增开发手册和安全说明

### Changed
- 项目目录结构重组
- 发布产物与源码分离

### Removed
```

### 7.4 版本更新检查机制

更新检查由 Service + Store 两层协作完成：

| 层 | 文件 | 职责 |
|----|------|------|
| Service | `UpdateChecker.swift` | GitHub API 调用、版本比较、下载（异步 `URLSession.bytes` 带回调进度）、ditto 解压、文件完整性校验 |
| Store | `UpdateCheckerModel.swift` | `@MainActor ObservableObject`，管理状态机（idle / checking / upToDate / updateAvailable / downloading / downloadComplete / error）；启动时 `checkForUpdate()` 静默检查（24h 缓存），手动 `manualCheck()` 即时检查（忽略缓存），`dismissUpdate()` 重置 UI |

**数据流（双入口）**：
```
启动自动检查（静默，24h 缓存）：
[App 启动 .task]
    ↓ checkForUpdate()
[读取本地缓存 update-check.json]
    ↓ 24h 内命中 → 有更新则 state = .updateAvailable（显示 [更新] [稍后]）
    ↓ 缓存过期 → 静默 GET API → 有更新则 .updateAvailable

手动检查（用户触发，忽略缓存）：
[用户点击"检查更新"]
    ↓ manualCheck() → state = .checking
    ↓ GET api.github.com/repos/.../releases/latest
    ↓ semverCompare(latest, current)
[无更新 → state = .upToDate(version) → 显示"已是最新版本 vX.Y.Z" 3s自消]
[有更新 → state = .updateAvailable(version) → 显示 [更新] [稍后]]

下载安装：
[用户点击"更新"]
    ↓ startDownload() → URLSession.bytes → 进度回调 → 进度 fill 动画
    ↓ 下载完成
[校验文件大小 × Content-Length 交叉验证]
    ↓ ditto -x -k 解压
[state = .downloadComplete → 用户点击"安装" → NSWorkspace.open(.app)]
```

- 下载文件存放于 `Application Support/com.yanghaoran.CodexTokenCost/updates/`
- 检查时间戳缓存在 `config/update-check.json`，24 小时内不重复请求
- 所有网络请求使用 `URLSession(configuration: .ephemeral)`，无持久化 cookie/cache

## 8. 安全边界

- 本应用**只读**访问 OpenCode 数据库和 Codex session 文件
- 不修改任何源数据文件
- 语言设置、总览计价偏好、Provider 计费方案选择和余额监控配置（含 Provider 开关与环境变量策略）只写入本地 `config/app-preferences.json`，不接触源数据
- 总览页的总成本按 `combinedMonthlyCost` 计算：已启用固定订阅费用 + 未订阅部分 API 估算成本；全部订阅关闭时全量 API 估算
- 本地化资源只读加载，不会反向写回源数据或网络
- 配置和快照仅写入 `~/Library/Application Support/com.yanghaoran.CodexTokenCost/`
- Helper 子进程通过标准 OS 进程隔离运行
- 文件写入通过 `SafeFileStore` 防止路径穿越（v0.6.0 增加 `..` 路径组件早期拒绝）
- 无网络请求、无数据上传——除 GitHub Release 版本更新检查（启动自动静默 + 可选手动即时检查，仅匿名 GET `api.github.com`，不传数据）和可选手动开启的 Provider 余额查询（HTTPS 直连各 Provider 官方 API）外；OpenCode Go 设置页的「测试连接」也仅复用同一条官方 HTTPS 查询路径，不写入额外持久化数据；浏览器凭证导入仅读取 opencode.ai 域名 cookie，在本地解密后存入 Keychain，需用户确认；环境变量凭证仅读取 `OPENCODE_GO_WORKSPACE_ID` / `OPENCODE_GO_AUTH_COOKIE`，且必须由用户在设置中显式开启
- 浏览器临时文件（Cookie/History SQLite 副本）写入沙箱专用子目录，权限 0700，操作完成后自动清理（v0.6.0）
- 更新下载的 .app bundle 解压后经 `codesign --verify` 签名校验（v0.6.0）
- 扫描根路径白名单校验，禁止添加 `/`、`/System`、`/Users` 等系统根路径（v0.6.0）
- Keychain 写入增加 `SecItemDelete` 返回值检查，防止旧凭证残留（v0.6.0）
- `scenePhase` 终止钩子确保 app 退入后台时所有设置域最终落盘（v0.6.0）
- 所有设置通过 `.atomic` 原子写入并在覆盖前保留最近 10 份备份；不做主线程写后 sleep 回读校验（v0.6.0）
- Skills 管理面板（v0.7.0）只读分析 skill 权限配置，不修改 OpenCode 任何文件；支持多维过滤、Section 分组、Skill 正文预览，Settings 页可调整显示偏好
- 趋势图和热力图（v0.8.0）仅基于已读取的 OpenCode / Codex 本地聚合数据做派生展示，不新增网络请求或源数据写入
- 窗口关闭时仅切换 `NSApp.setActivationPolicy(.accessory)` 从 Dock/App Switcher 隐藏，不新增数据访问、文件写入或网络请求；通过 MenuBar 重新打开窗口时恢复 `.regular` 策略
