# 开发手册

## 1. 项目概述

**Token Cost App - OC Codex** 是一个 macOS 原生桌面应用，用于可视化 AI 编程工具（OpenCode / Codex）产生的 token 用量和费用数据。

- **语言**: Swift 6.0+
- **UI 框架**: SwiftUI + AppKit (部分)
- **构建系统**: Swift Package Manager (SPM)
- **最低系统**: macOS 14.0 (Sonoma)
- **仓库**: [GitHub](#) · MIT License

### 数据源

| 数据源 | 格式 | 默认路径 |
|--------|------|---------|
| **OpenCode** | SQLite 数据库 | `~/.local/share/opencode/opencode.db` |
| **Codex** | JSONL 文本文件 | `~/.codex/sessions/` |

## 3. 模块架构

### 3.1 CodexTokenCostCore（核心库）

最底层模块，不依赖 AppKit / SwiftUI。被 App 和 Helper 共享引用。

| 文件 | 职责 |
|------|------|
| `Models.swift` | 数据模型：`TokenCostSource`, `TokenCostSettings`, `DashboardPayload`, `UsageAggregateRow` |
| `AppPreferences.swift` | 全局偏好：语言、总览计价模式、Provider 计费方案选择、本地持久化 |
| `BillingPlanCatalog.swift` | Provider 计费计划目录：OpenCode、ChatGPT/Codex、MiniMax、Xiaomi MiMo 官方预设与自定义 USD 月费解析；订阅周期设置（`PeriodGranularity`/`PeriodPreset` enum + `BillingPlanSelection` 的 `periodStart`/`periodEnd`/`periodGranularity`/`periodPreset`/`hasPeriodTracking` 字段）；`periodTotalCost(for:)` 按日/月粒度折算单个 provider 的完整周期总成本（包含式日历日，起止均计入）；`combinedPeriodCost()` 汇总所有 provider；`reportingCostBreakdown(payload:reportingStart:reportingEnd:)` 是全局报告范围规范总成本入口——Phase 1 将各 provider 的独立周期成本按重叠天数分摊到报告范围（零重叠贡献 0，不回退月费），Phase 2 筛选报告范围内日期行补充未覆盖的 API 用量成本；`filteredPayloadWithReportingOverrides` 按报告范围过滤 rawData 并重建聚合字段；`resolveReportingRange(mode:customBounds:payload:)` 支持 allAvailable/currentMonth/last30Days/custom 四种模式 |
| `Localization.swift` | 语言切换与本地化资源加载 |
| `CodexModels.swift` | Codex 专用模型：`CodexTokenUsage`, `CodexSessionSummary`, `CodexDashboardPayload` |
| `DashboardAnalytics.swift` | 分析引擎：将原始行转为 Overview / Cache / Provider Rank / Model Comparison / Distribution / Trend / Stacked。**含模型定价目录**（`TokenCostPricingCatalog`）。**Ollama Cloud 缓存读估算**：当 `ollama-cloud` Provider 下 `cacheRead == 0` 且 `input > 0` 时，基于 2026-07 快照对 `deepseek-v4-flash`/`deepseek-v4-pro` 估算 `estimatedCacheRead = input × (rate / (1−rate))`；估算值仅影响展示口径（`CacheSummary.cacheReadTokens`、`ProviderCacheRow`、趋势图），不落地源数据，不影响计费 `actualTokens`、`cost` 和 `cacheSavedCost`。**详情排序**：`sortedDetailRows(sortField:direction:)` 基于全量 `rawRows` 排序，支持 date/model/provider/input/output/cacheRead/cacheWrite/total/cost 字段。**堆叠图**：`buildStackedSeries` 取 top-8 模型 + Other，覆盖全量日期范围。**缓存命中率**：`cacheHitRate = displayedCacheRead / (totalInputTokens + displayedCacheRead)`，分母为输入 + 展示缓存读。**估算字段**：`CacheSummary`/`ProviderCacheRow`/`TrendPoint` 均含 `estimatedCacheReadTokens` 和 `hasEstimates` |
| `CodexAnalytics.swift` | Codex 分析：session 排序、日期桶聚合、趋势点生成 |
| `TokenHeatmapBuilder.swift` | 双源热力图数据构建：合并 OpenCode / Codex 日 token、生成 52 周窗口、输出 7x52 兼容矩阵和按日期升序的响应式 cells |
| `CodexBilling.swift` | 废弃常量（不再参与主计算链） |
| `TokenDatabaseClient.swift` | SQLite 客户端：探针 + `json_extract` 查询 + 构建 `DashboardPayload` |
| `SourceDiscoveryService.swift` | 文件系统扫描：遍历目录发现数据库文件。`lastModified` 字段以 ISO 8601 UTC 格式存储，UI 层通过 `TokenCostFormatters.localDateTime(_:)` 转换为用户系统时区显示 |
| `CodexSessionCollector.swift` | JSONL session 解析器：读取每行 JSON、提取 `session_meta` 和 `event_msg(token_count)` |
| `SourceProfiles.swift` | OpenCode / Codex 的默认路径、文件模式、扫描深度等配置 |
| `SettingsStore.swift` | 设置 + 快照文件的读写和轮转 |
| `SafeFileStore.swift` | 沙箱内安全文件操作（防止路径穿越） |
| `LocalEncryptedCredentialStore.swift` | 本地 AES-256-GCM 加密凭证存储（CryptoKit，无 Keychain 依赖）；密文 JSON + 独立 32 字节随机密钥文件，目录 0700 / 文件 0600，原子写入，每次写入使用全新 nonce |
| `LocalCredentialService.swift` | Core 凭证 facade，包装 `LocalEncryptedCredentialStore`；提供 Go workspace ID / Go auth cookie / Ollama cookie 的增删改查和 `discoverCredentials(allowEnvironment:)`；`importLegacyKeychainCredentials()` 是唯一显式访问 `SecureCredentialStore` 的路径 |
| `SecureCredentialStore.swift` | 旧版 Keychain 凭证存储（仅作为显式 legacy 导入源，默认运行时不调用） |
| `UpdateChecker.swift` | GitHub Release 检测、.zip 下载（异步进度回调）、完整性校验、ditto 解压、原子替换安装 + detached shell 延迟重启 |
| `PathUtilities.swift` | 路径标准化、descent 检查 |

### 3.4 应用级偏好与本地化

应用级偏好不和 OpenCode / Codex 各自的数据源设置混用，而是单独保存：

- `AppPreferencesStore` 负责把 `language`、`openCodePricingMode`、`billingSelectionsByProvider`、`theme`、`displayCurrency`、`balanceEnabled`、`balanceRefreshMinutes`、`balanceConfig` 写入本地 `config/app-preferences.json`
- `AppPreferencesModel` 是 SwiftUI 侧的单一状态入口，负责保存和广播语言切换、主题变更。采用内存缓存 + 写穿透模式：UI 从 `@Published preferences` 内存读取，变更时通过 `SafeFileStore` 以 `.atomic` 原子写入 JSON，并在覆盖前保留备份；不做主线程写后 sleep 回读校验
- 余额监控相关的 Provider 开关和 `allowEnvironmentCredentials` 不允许在 View 中直接改 `preferences.balanceConfig` 嵌套字段，而是统一经 `AppPreferencesModel.updateBalanceConfiguration()` 修改并立即持久化，避免运行时状态与磁盘状态短暂漂移
- `AppPreferencesModel` 也负责 OpenCode Go `workspaceID` 的兼容同步：保留 `app-preferences.json` 中的副本，用户编辑保存时写入本地加密凭证存储（`LocalCredentialService`），供运行时凭证发现链路读取；Settings 页提供「测试连接」按钮用于验证当前 OpenCode Go 凭证
- `SettingsView` 已按 `全局偏好 / 计费方案 / 余额监控 / OpenCode / Codex / Skills 面板 / 安全边界` 分组；一级模块可折叠，warning banner 常驻顶部，OpenCode / Codex 的长路径列表保留二级折叠与分页；模块内部统一使用响应式控制网格、动作条和字段区，默认在 900 宽设置窗口内优先两列排布，窗口变宽后再扩到更多列
- `BalanceManager` 在 App 启动时从 `AppPreferences.balanceConfig` 初始化，并在设置变更时热更新；OpenCode Go 只有在 `allowEnvironmentCredentials == true` 时才允许读取 `OPENCODE_GO_WORKSPACE_ID` / `OPENCODE_GO_AUTH_COOKIE`；单 Provider 的测试连接通过 `testSnapshot(for:authToken:)` 绕过全局 backoff，成功/失败结果可用 `upsertSnapshot(_:)` 写回内存快照列表并保持 Provider 排序
- `BalanceRefreshScheduler` 在 App 初始化后启动应用生命周期级余额刷新循环；它每 10 秒检查 `balanceEnabled` 和 `balanceRefreshSeconds`，再进入 `BalanceManager.refresh()` 的 `isRefreshing`、backoff 与 Provider 守卫。`ContentView` 不再持有余额刷新 Timer，只在回到 `.active` 时执行一次 catch-up 检查；进入后台或非活跃状态时仍强制执行设置落盘（`persistPreferences()` + `persistSettings()`）
- `AppLocalization` 从 `Resources/<lang>.lproj/Localizable.strings` 读取文案，并在 App 运行时根据语言切换刷新 UI
- 总览页只读取 `openCodePricingMode`；其中 OpenCode 的“实际 token”指标按 `input + output + reasoning` 计算（各字段含义与 OpenCode 源码 `getUsage()` 存储逻辑一致：`input` 在 SQLite 中已是非缓存输入，`output` 为非推理输出，`reasoning` 为推理 token，`cacheRead`/`cacheWrite` 为独立缓存字段），OpenCode / Codex 独立页面仍保留各自原有 token 统计与展示口径
- Provider 订阅成本通过 `BillingPlanCatalog` 解析：每个 Provider 独立判断——已启用固定订阅算月费，否则走 API/raw/synthetic cost。总成本 = 已启用固定订阅费用 + 未订阅部分 API 估算成本；全部订阅关闭时总成本全部按 API 估算。选择 DIY 时统一按 USD/月保存并注入 `TokenCostDashboardAnalytics` 的 provider effective cost
- **Provider 独立订阅周期**：每个 Provider 拥有独立的 `periodStart`/`periodEnd`（包含式日历日，起止均计入）、`periodGranularity`（`.day` 或 `.month`）和 `periodPreset`（monthly/quarterly/yearly 快捷填充）。`periodTotalCost(for:)` 按粒度折算该 provider 的完整周期总成本。`hasPeriodTracking` 开关控制是否启用周期跟踪；关闭时回退月费口径（`monthlyUSD`）。原生 SwiftUI `DatePicker`（`.date` 模式）直接作为起止日期输入控件，不做额外日期转换
- **全局报告范围（Reporting Range）**：`reportingRangeMode`（`allAvailable`/`currentMonth`/`last30Days`/`custom`）定义全局报告窗口。`reportingCostBreakdown(payload:reportingStart:reportingEnd:)` 是规范总成本入口：Phase 1 遍历各 provider，对有 `hasPeriodTracking` 且周期与报告范围重叠的，按 `cycleTotalCost × overlapDays / cycleIncludedDays` 分摊到报告范围；无重叠贡献 0；无周期/无效日期回退完整 `monthlyUSD`。Phase 2 补充报告范围内未被固定订阅覆盖的 API 用量成本。`combinedTotalCost(payload:)` 优先使用 `reportingCostBreakdown`，payload 无法形成有效范围时回退 `combinedMonthlyCost`
- `PricingDocView` 是 App 内置只读计费参考，当前以 SwiftUI 原生卡片和表格硬编码展示 Provider 订阅档位、MiMo Credit 规则和总成本口径；不打开任意本地路径、不访问网络。计费文档与开发者模式文档均通过独立 `Window` scene 打开，而不是设置页 sheet
- 技术词统一保留英文写法，例如 `token`、`API`、`OpenCode`、`Codex`、`ChatGPT Plus`

## 4. 数据流

### 4.1 OpenCode 数据管线

```
[文件系统扫描]
SourceDiscoveryService
    ↓ discover()
[SQLite 数据库列表] → TokenCostSource[]
    ↓ 用户选择来源
[TokenDatabaseClient.loadPayload()]
    ↓ SELECT json_extract(...) FROM message
[UsageAggregateRow[]]
    ↓ buildPayload()
[DashboardPayload]
    ↓ TokenCostDashboardAnalytics 初始化（可接收 billingOverridesByProviderKey）
[Overview / Cache / Provider / Model / Distribution / Trend]
    ↓ 各 View 读取
[UI 渲染]
```

**关键 SQL**: 使用 `json_extract(data, '$.tokens.input')` 等从 JSON 列提取字段，按 `date, model_id, provider_id` 分组聚合。日期列通过 `date(time_created/1000, 'unixepoch', 'localtime')` 将毫秒时间戳转为当前机器时区的日历日字符串，所有按日聚合的指标均遵循此本地时区边界。

### 4.2 Codex 数据管线

```
[用户在设置中配置 session 目录/文件]
    ↓
[CodexHelperRunner.loadPayload()]
    ↓ 启动子进程
[CodexTokenCostHelper (外部进程)]
    ↓ 遍历 JSONL 文件
[CodexSessionCollector.loadPayload()]
    ↓ 逐行解析 session_meta / event_msg
[CodexDashboardPayload]
    ↓ stdout JSON → 主进程解码
[CodexSessionModel.payload]
    ↓ CodexDashboardAnalytics 分析
[UI 渲染: 趋势图 + Session 列表]
```

**Error 处理**: Helper 进程超时 15s，失败自动回退到本地快照 `~/Library/Application Support/com.yanghaoran.CodexTokenCost/snapshots/codex/`。

### 4.3 悬浮余额面板数据流

```
[App 启动]
    ↓ TokenCostApp.init() 创建 BalanceFloatingPanelCoordinator
    ↓ AppDelegate.applicationDidFinishLaunching() → requestInitialPresentation()
[读取 AppPreferences.balanceFloatingPanelEnabled]
    ↓ true → ensurePanel() 创建 BalanceFloatingPanelWindow (NSPanel)
[BalanceFloatingPanelWindow]
    ├── styleMask: .borderless, .resizable, .fullSizeContentView, .nonactivatingPanel
    ├── canBecomeKey: false, canBecomeMain: false
    ├── show(): orderFrontRegardless()（显示但不抢占焦点）
    ├── level: .floating (始终置顶)
    ├── collectionBehavior: [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary]
    ├── hidesOnDeactivate: false (跨桌面常驻)
    ├── isOpaque: false, backgroundColor: .clear (透明背景，不再设置 pageBackground)
    └── contentView: NSHostingView<BalanceFloatingPanelView> (focusRingType: .none)

[BalanceFloatingPanelView 渲染]
    ├── shellBackdrop (双层方案)
    │   ├── macOS 26+ → .glassEffect(.regular.tint(accentSoft)) Liquid Glass
    │   └── macOS 14–25 → VisualEffectBackground (NSVisualEffectView)
    │       ├── blendingMode: .behindWindow (合成桌面内容)
    │       ├── state: .active (失焦时保持清晰)
    │       ├── material: .hudWindow
    │       └── layer.cornerRadius + masksToBounds (圆角裁剪)
    ├── 边框: surfaceAccessibleStroke 双层细线 (0.55 + 0.35 透明度)，替代蓝色 surfaceStroke
    ├── widget 状态区: 状态点 + 标题 + 刷新时间 + hover-only 圆形刷新/关闭操作
    ├── 空态: 引导文案 + ProviderLogoMark
    └── 有数据 → ScrollView + LazyVGrid
        ├── displayMode == .normal → BalanceProviderCardView（完整信息卡）
        └── displayMode == .minimal → BalanceMinimalProviderTile（轻量纵向指标磁贴）
            ├── 有进度数据 → 54pt 圆形进度环 + 居中百分比
            └── 无进度数据 → 密度符号回退
        └── 列数: BalanceFloatingPanelLayout.gridColumns()
            ├── usableWidth = panelWidth - 2 × contentPadding
            ├── columns = floor((usableWidth + gap) / (tileMinimumWidth + gap))，限制为 1–4 且不超过 Provider 数量
            └── 默认 480pt: normal 2 列（minimum 210pt），minimal 4 列（minimum 106pt）

[用户交互]
    ├── 关闭按钮 → onRequestClose → Coordinator.close() → orderOut + 写回 preferences.balanceFloatingPanelEnabled = false
    ├── 外部 close 事件 → windowShouldClose → 同上（borderless panel 无原生 red button）
    ├── 菜单栏「悬浮面板」按钮 → toggleFromMenuBar() → 翻转 preferences.balanceFloatingPanelEnabled
    ├── 设置页开关 → balanceFloatingPanelEnabledBinding → 持久化 → Coordinator 监听 → show/hide
```

### 7.4 版本更新检查机制

更新检查由 Service + Store 两层协作完成：

| 层 | 文件 | 职责 |
|----|------|------|
| Service | `UpdateChecker.swift` | GitHub API 调用、版本比较、下载（异步 `URLSession.bytes` 带回调进度）、ditto 解压、文件完整性校验、原子替换安装 + detached shell 延迟重启 |
| Store | `UpdateCheckerModel.swift` | `@MainActor ObservableObject`，管理状态机（idle / checking / upToDate / updateAvailable / downloading / downloadComplete / error）；启动时 `checkForUpdate()` 静默检查（24h 缓存），手动 `manualCheck()` 即时检查（忽略缓存），`dismissUpdate()` 重置 UI，`installUpdate()` 原子替换 + 通知持久化 + 重启 |

**数据流（双入口）**：
```
启动自动检查（静默，24h 缓存）：
[App 启动 .task]
    ↓ checkForUpdate()
[读取本地缓存 update-check.json]
    ↓ 24h 内命中 → 有更新则 state = .updateAvailable（显示 [更新] [稍后]）
    ↓ 缓存过期 → 静默 GET API → 有更新则 .updateAvailable

手动检查（用户触发，忽略缓存）：
[用户点击"检查更新"]
    ↓ manualCheck() → state = .checking
    ↓ GET api.github.com/repos/.../releases/latest
    ↓ semverCompare(latest, current)
[无更新 → state = .upToDate(version) → 显示"已是最新版本 vX.Y.Z" 3s自消]
[有更新 → state = .updateAvailable(version) → 显示 [更新] [稍后]]

下载安装：
[用户点击"更新"]
    ↓ startDownload() → URLSession.bytes → 进度回调 → 进度 fill 动画
    ↓ 下载完成
[校验文件大小 × Content-Length 交叉验证]
    ↓ ditto -x -k 解压
[state = .downloadComplete → 用户点击"安装并重启" → installUpdate()]
    ↓ replaceAppBundle() — 旧 app rename 为 .old，新 app move 到原位（同卷原子操作）
    ↓ persistBeforeRelaunch() — 广播 .appWillRelaunchForUpdate 通知 → 各 model 落盘
    ↓ scheduleRelaunch() — detached shell: sleep 1; open <path>
    ↓ NSApp.terminate(nil) — 旧实例退出
[1 秒后 detached shell 打开新 app → 单实例启动]
```

- 下载文件存放于 `Application Support/com.yanghaoran.CodexTokenCost/updates/`
- 检查时间戳缓存在 `config/update-check.json`，24 小时内不重复请求
- 所有网络请求使用 `URLSession(configuration: .ephemeral)`，无持久化 cookie/cache
- 安装采用原子替换（rename 旧 app → .old，move 新 app → 原位），detached shell 延迟 1s 重启，保证单实例
- AppDelegate 启动时清理上次替换留下的 .old 备份

## 8. 安全边界

- 本应用**只读**访问 OpenCode 数据库和 Codex session 文件
- 不修改任何源数据文件
- 语言设置、总览计价偏好、Provider 计费方案选择和余额监控配置（含 Provider 开关与环境变量策略）只写入本地 `config/app-preferences.json`，不接触源数据
- 总览页的总成本按 `combinedMonthlyCost` 计算：已启用固定订阅费用 + 未订阅部分 API 估算成本；全部订阅关闭时全量 API 估算
- 本地化资源只读加载，不会反向写回源数据或网络
- 配置和快照仅写入 `~/Library/Application Support/com.yanghaoran.CodexTokenCost/`
- Helper 子进程通过标准 OS 进程隔离运行
- 文件写入通过 `SafeFileStore` 防止路径穿越（v0.6.0 增加 `..` 路径组件早期拒绝）
- 无网络请求、无数据上传——除 GitHub Release 版本更新检查（启动自动静默 + 可选手动即时检查，仅匿名 GET `api.github.com`，不传数据）和可选手动开启的 Provider 余额查询（HTTPS 直连各 Provider 官方 API）外；OpenCode Go 设置页的「测试连接」也仅复用同一条官方 HTTPS 查询路径，不写入额外持久化数据；浏览器凭证导入仅读取 opencode.ai / ollama.com 域名 cookie，在本地解密后存入本地 AES-256-GCM 加密凭证存储，需用户确认；环境变量凭证仅读取 `OPENCODE_GO_WORKSPACE_ID` / `OPENCODE_GO_AUTH_COOKIE`，且必须由用户在设置中显式开启
- 本地加密凭证存储（`LocalEncryptedCredentialStore`）使用 CryptoKit AES-256-GCM 加密，密文 JSON + 独立 32 字节随机密钥文件分离存储；目录权限 0700，文件权限 0600，原子写入，每次写入使用全新随机 nonce；默认运行时不访问 Keychain，避免本地构建 app 触发系统授权弹窗；旧 Keychain 凭证可通过设置页「从 Keychain 导入」按钮显式迁移到本地加密存储
- 浏览器临时文件（Cookie/History SQLite 副本）写入沙箱专用子目录，权限 0700，操作完成后自动清理（v0.6.0）
- 更新下载的 .app bundle 解压后经 `codesign --verify` 签名校验（v0.6.0）
- 扫描根路径白名单校验，禁止添加 `/`、`/System`、`/Users` 等系统根路径（v0.6.0）
- Keychain 写入增加 `SecItemDelete` 返回值检查，防止旧凭证残留（v0.6.0）
- Ollama Cloud cookie 存储统一使用本地 AES-256-GCM 加密凭证存储（与 OpenCode Go 凭证一致），`saveOllamaCookie` 返回 `Bool` 确认写入结果；legacy DPK domain cookie 和 Keychain 旧凭证可通过设置页显式导入（v0.9.7 迁移至 Keychain，后改为本地加密存储）
- Ollama Cloud 余额监控解析 5 小时窗口（`aria-label="Session usage NN%"`）和每周限额窗口（`aria-label="Weekly usage NN%"`）的百分比与 `data-time` ISO 8601 重置时间戳，构建双 `BalanceQuotaWindow` 填充 `primaryWindow`/`secondaryWindow` + `quotaWindows`；Strategy 1 正则使用 `%[^"]*"` 兼容 `aria-label="Session usage 51% used"`（` used` 后缀）和旧无后缀格式；新增 `extractPlanType()` 从 `Cloud usage` 标签后 `<span>` 解析 plan 名称（free/pro/max）写入 `BalanceSnapshot.planType`；保留旧三重降级 fallback 应对 HTML 结构变更；不新增网络 endpoint，仍用 `https://ollama.com/settings` GET 请求（v0.9.7）
- `ConsumptionRateCalculator` 仅存储用量百分比和时间戳到 `UserDefaults.standard`（key: `com.token-cost-app.balance-history`），不含凭证、Cookie 或个人信息；历史采样上限 200 条/窗口，自动清理过期数据（v0.9.7）
- `scenePhase` 终止钩子确保 app 退入后台时所有设置域最终落盘（v0.6.0）
- 所有设置通过 `.atomic` 原子写入并在覆盖前保留最近 10 份备份；不做主线程写后 sleep 回读校验（v0.6.0）
- Skills 管理面板（v0.7.0）只读分析 skill 权限配置，不修改 OpenCode 任何文件；支持多维过滤、Section 分组、Skill 正文预览，Settings 页可调整显示偏好
- 趋势图和热力图（v0.8.0）仅基于已读取的 OpenCode / Codex 本地聚合数据做派生展示，不新增网络请求或源数据写入
- 窗口关闭时仅切换 `NSApp.setActivationPolicy(.accessory)` 从 Dock/App Switcher 隐藏，不新增数据访问、文件写入或网络请求；通过 MenuBar 重新打开窗口时恢复 `.regular` 策略
- 悬浮余额面板（`BalanceFloatingPanelWindow`）使用无边框 `NSPanel`，`level: .floating` 始终置顶，`collectionBehavior: [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary]` 跨桌面常驻；`hidesOnDeactivate = false` 确保切换 app 时不自动隐藏；`isOpaque = false` + `backgroundColor = .clear` 实现透明背景（已移除 `pageBackground`，不再泄漏蓝色主题渐变）；面板关闭仅 `orderOut` 不释放窗口，不新增数据访问或网络请求

## 9. 开发原则

### 9.1 新功能优先放置到开发者模式

**所有新功能必须首先在开发者模式（Developer Mode）中实现和验证**，而不是直接暴露在常规 UI 中。

**流程**：
1. 在 `DeveloperModePreferences` 中添加子功能开关
2. 在 `SettingsView` 的 `developerSection` 中添加 UI 控件
3. 实现功能逻辑，通过子功能开关控制启用/禁用
4. 编写单元测试，在开发者模式中验证功能
5. 功能稳定后，迁移到常规 UI

**理由**：
- 降低新功能对普通用户的干扰
- 提供安全的实验环境
- 符合"渐进式披露"的 UI 设计原则

### 9.2 功能毕业条件

一个功能从开发者模式毕业到常规 UI，需要满足：

| 条件 | 说明 |
|------|------|
| 功能完整性 | 所有计划功能已实现 |
| 测试覆盖 | 单元测试和集成测试通过 |
| 用户验证 | 在开发者模式下经过充分测试 |
| 无已知缺陷 | 无 P0/P1 级别的 bug |

### 9.3 设置面板原则

- 使用 `NavigationSplitView` + 侧边栏选择模式
- 操作按钮放在其**所属功能的上下文中**，不放在全局概览区域
- 不在多个 tab 中重复显示相同的控件

## 10. GitHub 集成

| 功能 | 文件 | 说明 |
|------|------|------|
| CI 自动编译 | `.github/workflows/ci.yml` | push/PR 时编译验证 |

### GitHub Release 发布步骤

1. 完成功能开发，更新 CHANGELOG.md（保持 `Unreleased` 为下一版）和 SECURITY.md
2. 打 tag：`git tag -a v0.X.X -m "Release notes"`
3. 推送：`git push origin v0.X.X`
4. 等 `release.yml` 完成打包并在 GitHub Releases 查看产物
5. 如有需要，再手动补充 Release Notes
